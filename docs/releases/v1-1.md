# v1.1 — Replace the Supabase client with a bespoke backend

- **Status:** **undesigned, not committed — NOT scheduled.**
- **Origin:** carried from `docs/feedback-and-improvements.md` (§ v1.1) on the 2026-07-12 docs split;
  never discussed in depth.
- **Problem, go/no-go gate & recommendation:** see **PRD-3**
  (`docs/prd/PRD-3-bespoke-backend-replacement.md`) — authoritative. PRD-3 is a **decision artifact**,
  not a feature spec; this release doc carries only the scheduling stance.

## Scheduling stance

**Do not schedule.** This becomes schedulable only once **PRD-3's go/no-go gate is met** — a concrete
motivating problem named (not "Supabase is a dependency"), the smaller-change alternative (Edge
Functions) ruled out, and the ongoing ops cost explicitly accepted. Until then there is nothing to
plan. (Full gate + open questions: PRD-3.)

## Delivery model

**None — nothing ships until this is scheduled**, and it is not. No version / OTA / APK / migration
applies yet.

## Scope guard

**Do not chain this to PRD-2 / v1.0.4.** PDDIKTI verification is served by a Supabase **Edge Function**
— precisely the "smaller change" PRD-3's gate names, and an argument for **keeping** Supabase, not
replacing it.
