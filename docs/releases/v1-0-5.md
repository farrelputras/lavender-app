## Size — read this before planning

Farrel opened this release asking for something **simple and short**. He was shown the short cut line
and **chose the full one instead** (2026-07-25). Recording that here so nobody later reads the scope as
drift:

- The short option was *style-only on `PengembalianScreen`* — apply the field box to its local inputs
  without swapping components, exactly the waiver v1.0.4 already took on that screen. It would have
  delivered AC-1, AC-2, BR-7 and BR-8 with no fence opened.
- **The chosen option is full PRD-8, including D-5.** That opens debt **#4**'s fence on
  `PengembalianScreen`, which makes debt **#15**'s missing test suite a **precondition** (BR-12), not a
  ride-along. PRD-8's own §What this costs calls that suite "the single largest line item in the release."

**This is the largest release since v1.0.3, and it is the first one to open a rental-math screen
deliberately.** What it buys: the first automated coverage `PengembalianScreen` has ever had, and the
first real dent in debt #4. Plan it as a fenced migration, not as a polish pass.

### The one criterion this release must amend: AC-4

PRD-8 **AC-4** reads: *"On `RentalDetailScreen`, no `surfaceContainerLow` single-value block remains
(Tujuan, read-only Catatan), and **nothing on the screen renders in the field box** — it is read-only
under D-4."*

**Its second half is unsatisfiable in a PRD-8-only release.** D-4 assumes PRD-6's dedicated rental edit

inventory lists both as ✅ editable, treatments #8 and #6). Shipping "nothing gets a box" would leave two

## Sequencing & guards

**Order** (PRD-8's own advisory sequencing, adopted as binding):

1. **Characterisation tests first, as their own verifiable step**, written against untouched `master`
   behaviour and green **before anything moves**. This is the AC-9 baseline. A suite written after the
   migration pins whatever the migration produced — including its bugs.
2. **The primitive** (BR-1/BR-3/BR-6, one definition site in `app/components/form/`) **+ the two form
   screens** (`UserFormScreen`, `HutangFormScreen` — AC-3). Low risk, high signal, and it proves the
   convention before it reaches dangerous code.
3. **The strips** — `RentalDetailScreen` AC-4a + AC-4c, `UserDetailScreen` AC-5.
4. **The `PengembalianScreen` D-5 migration** (AC-1, AC-2) — last, behind a green step 1.
5. **The durability layer** — source audits AC-6/AC-7, contrast test AC-8.
6. **The ride-along** — remove the `fontScale` diagnostic footer. Independent of everything above;
   do it whenever, but do not let it be forgotten (that is how it survived v1.0.4).

**Guards — do not fold, do not absorb:**

1. **Do not change the `returnedAt` default.** PRD-8 **OQ-2** puts the *Kembali* row in scope for
   *styling*. Debt **#16** is about that row's **value** — it seeds `new Date()` at screen-open, has
   already produced one wrong persisted record, and has no in-app correction path. **Styling the row is
   safe; re-seeding it is not**, and fixing it properly needs an RPC and a permission-matrix extension
   this release is forbidden to open (BR-9). This is the single most likely misread available here.
2. **Do not widen D-5's depth.** Input-bearing primitives **only**. Local `SectionLabel`, `FuelGauge`,
   `Stepper` and the local bottom action bar **stay put**. The two `FuelGauge` copies have already
   diverged on `max` (debt #4) — migrating that one is a *behavioural* change on a money path wearing a
   refactor's clothes.
3. **Do not "fix" debt #12 while you are in there.** Both of its `docs/02` §6 ↔ code divergences live in
   `PengembalianScreen` and will be directly under the cursor during step 4: the fuel suggestion writes
   an extra-fee line instead of adjusting Subtotal, and the suggestion row renders amber
   unconditionally. **Neither has money impact today, and which side is wrong — the code or §6 — is an
   open Product question.** Touching either turns a presentation release into a math change.
4. **No math moves.** D-5 is a component swap. AC-9 exists to prove the calculations came through
   identical; it cannot prove that if the calculations were edited.
5. **No server surface.** No migration, no RPC, no RLS, no change to `editLogic.ts`'s
   `canEditKondisiKeluar` / `canEditNotes` (BR-9, AC-11). PRD-1's permission matrix is untouched.
6. **Do not fold in `DetailSewaScreen`** (D-6). Once the primitive exists it will look like a
   twenty-minute win. It is tariff composition behind the same debt #4 fence, and opening two rental-math
   screens in one release is how a fenced migration stops being fenced.
7. **Do not fold in PRD-6.** The convention must be settled and shipped before the edit screen consumes
   it. That is D-1's whole point.
8. **Do not run `eslint --fix` or `prettier --write` across the repo** — debt **#6a**. A CRLF
   renormalization must be its own whitespace-only commit.

## Rollback

**Fully OTA-revertible.** No migration, no Edge Function, no schema or privilege change — nothing this
release does survives republishing the previous update group. Find it with
`eas update:list --branch preview` and republish.

**Two distinct triggers, and they need different responses:**

| Trigger | Response |
|---|---|
| **Presentation** — a field reads wrong, a control is unreachable, text clips at her size | Republish first, diagnose after. Same as v1.0.4. |
| **A number is wrong on the return screen** — subtotal, fuel adjustment, `Sisa`, or a hutang that should not exist | Republish **immediately**, then treat it as a money defect: audit any rental closed since publish, the way v1.0.3's `deleted_at` regression was audited. This trigger did not exist in v1.0.4 and exists now **because D-5 was taken**. |
